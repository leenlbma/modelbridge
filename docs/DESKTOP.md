# ModelBridge 桌面客户端

v0.3.2 是可安装的 Electron 应用。支持 macOS 14+、Apple Silicon；仅下载缺少的环境或组件时需要互联网。它不是离线安装包，也不含模型账号或服务额度。

## 使用

1. 从 DMG 把 ModelBridge.app 拖到“应用程序”，或解压 ZIP 后移动应用。
2. 打开后先检查本机环境。已运行的兼容后台直接使用；已安装但未运行时点击“启动已有服务”。安装或升级前会显示 Python 检测结果，已有可用环境直接复用，仅缺失时下载。安装窗口可关闭，客户端继续处理；处理期间暂不允许退出整个客户端。
3. 选择服务，填写自己的 Key 和模型，通过验证后导出 Claude 配置。具体 Claude 设置见主 README。
4. 关闭窗口后可用菜单栏图标或 Dock 再打开。退出客户端不会停止网关。状态与帮助中“停用后台服务”会停止网关并取消登录启动，保留文件以便恢复。

此包仅有 ad-hoc 本机签名，尚未经过 Developer ID 签名及 Apple 公证；从其他电脑下载时可能被 Gatekeeper 阻止。确认来源后可在系统设置 → 隐私与安全性中允许本次打开。不会提供关闭系统安全功能的安装脚本。

## 安装和升级

新安装使用 `~/Library/Application Support/ModelBridge`。已有旧版安装则复用原目录、端口、配置和后台标识；界面提供显式升级入口，升级前请结束 Claude 正在进行的回复。v0.1.0 在升级前为只读，不能向它提交其他供应商的 Key。

安装工具固定为 uv 0.11.21，随应用分发并核验 SHA256。Python 固定为 3.12.13，由 uv 从其官方 Python 构建渠道下载；依赖按 requirements.lock 从 PyPI 下载。运行环境和缓存写入安装目录的 tools，后台独立版本写入 releases。每个版本持有自己的 venv 和启动应用。客户端移动、重新打包或退出不影响已安装运行环境。

安装器在准备完依赖后才切换服务，切换前检查活动请求；启动失败尝试恢复旧 launchd 配置。临近切换时不要启动新模型任务。重试会复用下载缓存。失败的候选版本与旧版本保留用于检查，不自动清理用户数据。磁盘不足时可退出客户端后检查安装目录，不要删除当前 installation.json 指向的版本。

客户端 v0.3.2 可继续使用 v0.3.0 后台，不因客户端补丁版本变化强制重装。检测 Python 时先检查已有服务的解释器，再用 uv 离线查找；验证 CPython 版本、芯片架构、SSL 和 venv 可用性后，使用基础解释器。检查本身不下载文件。依赖安装先尝试离线缓存，只有缓存不足才联网。

“启动已有服务”校验原安装记录、运行环境和 launchd 配置，不创建新版本目录、不安装 Python 或依赖。若原环境损坏，界面提供明确的“检查并修复服务”，再次操作后才修复，不在一次启动失败后自动重装。

## 进程边界

- Renderer：加载随包页面，启用 sandbox、contextIsolation，关闭 nodeIntegration；CSP 禁止网络访问。
- Preload：仅提供状态、固定业务 API、导出、复制、安装管理与导航。
- Main：检查 IPC 来源；只向 127.0.0.1 上与安装记录相符的服务发送管理凭据。拒绝任意 URL、任意命令和任意文件读取。
- Gateway：launchd 管理的 Python 服务，与客户端生命周期分开。Key 只按当前服务配置使用，本地仅保留指纹。

## 开发和构建

开发依赖 Node >=22.12.0，执行 npm ci 后 npm start。源码开发模式需要先执行构建；安装资源位于构建应用内，未准备资源的开发模式不支持首次安装。可用已有后台测试界面。

`python3 scripts/build_desktop.py --dmg` 从校验通过的 Electron 42.11.15 官方包构建应用，附带 Electron/Chromium 与 uv 许可证，完成本地签名与严格校验，输出 ZIP、DMG 和 SHA256SUMS。构建缓存放在 .desktop-build。项目 LICENSE 与第三方声明同时进入应用与后台资源。`scripts/build_release.py` 单独生成源码 ZIP，不包含运行数据、密钥、测试截图和下载缓存。

隔离验收可给应用传 `--service-dir=绝对路径 --setup-label=com.modelbridge.acceptance.自定义标识`。只给目录不提供标签时禁止安装，防止误操作日常后台。此参数仅供开发验收，不出现在用户界面。

## 验证边界

已在现有 Mac 的全新安装目录、独立 Python 目录、独立依赖缓存中通过联网安装。已有系统权限和已安装的 Claude 不等于新 Mac；干净机器、重新登录、跨芯片和 Gatekeeper 验收仍待完成。协议层回归通过不代表新的真实供应商兼容性；Claude Design、Cowork、图片和长上下文继续标记为未验证。

## 早期配置迁移

已有 schema-2 配置保留明确的服务地址，旧的预设标识会转为自定义。schema-1 不包含地址，开源版不会推断原供应商；需要在设置中重新填写并验证，成功前保留原配置文件。旧目录与 launchd 标识仅用于本机升级兼容。
